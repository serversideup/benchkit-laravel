BenchKit ships with sensible, production-shaped defaults so results are **comparable across machines** out of the box. You can adjust everything from the settings drawer before a run — and any non-standard value is disclosed alongside the results.

## Presets

Every run starts from a preset:

- **Quick** (~2 min) — network, a short web-server load test, and the headline PHP CRUD numbers. Great for a fast read on a box.
- **Full** (~30+ min) — everything, including Geekbench and the complete PHP suite.
- **Custom** — toggle individual stages and tune the load.

## The standard web-server load

The web-server load test is a **closed-loop throughput (saturation) test**. Its "standard load" — shared by every run for comparability — is:

| Setting | Default | Range |
| --- | --- | --- |
| Duration | `30s` (Full) / `10s` (Quick) | 5–60s |
| Connections | `50` | 1–500 |
| Simulated I/O response | `100ms` | 0–1000ms |

The **simulated I/O response** is the delay the `/bench/io` route sleeps to model one outbound dependency call. Turn it up and watch worker mode's advantage shrink — it's the single most instructive knob in BenchKit. See [Benchmarks & methodology](/docs/benchmarks/web-server-load-test).

## OPcache is on by default

The shipped image enables OPcache (and JIT is available) so PHP numbers reflect a **real production setup**, not an unrealistic cold-interpreter baseline. Every run's **Environment panel** records the exact `php.ini` tuning that produced it — OPcache, JIT, memory, realpath cache, and (on FPM) the pool size.

::tip
Want the classic "how much does OPcache matter?" lesson? Run once with it on, once with `PHP_OPCACHE_ENABLE=0`, and compare. See [Customizing the image](/docs/configuration/customizing-the-image).
::

## Where results are stored

Completed runs are saved as JSON snapshots in `storage/app/runs`. Mount a volume there to keep history across restarts (see [Deployment options](/docs/getting-started/deployment-options)).
