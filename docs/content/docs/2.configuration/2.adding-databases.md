---
title: Adding a real database
description: Point BenchKit at MySQL or Postgres instead of the default SQLite.
---

By default BenchKit uses an in-process **SQLite** database so it runs with zero setup. That's great for a quick read, but SQLite removes connection cost and real data-volume/indexing behavior. For production-shaped numbers, point BenchKit at **MySQL or Postgres** — it's just standard Laravel configuration.

## Set the standard Laravel database variables

```yaml [compose.yml]
services:
  benchkit:
    image: serversideup/benchkit-laravel
    ports:
      - "80:8080"
    environment:
      - DB_CONNECTION=mysql   # or pgsql
      - DB_HOST=your-db-host
      - DB_PORT=3306
      - DB_DATABASE=benchkit
      - DB_USERNAME=benchkit
      - DB_PASSWORD=secret
    volumes:
      - benchkit-runs:/var/www/html/storage/app/runs

volumes:
  benchkit-runs:
```

Or with `docker run`:

```bash [Terminal]
docker run -p 80:8080 \
  -e DB_CONNECTION=mysql -e DB_HOST=your-db-host -e DB_PORT=3306 \
  -e DB_DATABASE=benchkit -e DB_USERNAME=benchkit -e DB_PASSWORD=secret \
  -v benchkit-runs:/var/www/html/storage/app/runs \
  serversideup/benchkit-laravel
```

## No migration step needed

BenchKit creates its benchmark tables **on demand** — there's no `artisan migrate` to run and no seeder. Point it at a reachable database and the DB-read route and PHP CRUD stage run against it automatically.

::note
The results **Environment panel** shows which database engine actually ran, so a MySQL run is always labeled as such — the config is disclosed with the numbers.
::

::warning
Changing the database only affects the benchmark *workload*. Run history and results are stored as files (see the runs volume), so swapping engines is safe.
::
