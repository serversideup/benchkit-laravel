[FrankenPHP](https://frankenphp.dev) is a modern PHP application server built for containers. Its headline feature is **worker mode** (via Laravel Octane): the framework boots once and stays resident, instead of bootstrapping on every request.

## Classic mode

The `frankenphp` image runs in classic (per-request) mode by default — directly comparable to `fpm-nginx`:

```bash [Terminal]
docker run -p 80:8080 \
  -v benchkit-runs:/var/www/html/storage/app/runs \
  serversideup/benchkit-laravel:frankenphp
```

## Worker mode (Octane)

To benchmark the worker model, start Octane with FrankenPHP — same image, just a different command:

```bash [Terminal]
docker run -p 80:8080 \
  -v benchkit-runs:/var/www/html/storage/app/runs \
  serversideup/benchkit-laravel:frankenphp \
  php artisan octane:start --server=frankenphp --host=0.0.0.0 --port=8080
```

Results are labeled with the mode that produced them (look for the **worker mode** badge), so shared results always say which mode was benchmarked.

## Reading the comparison fairly

Worker mode's saving is the **framework bootstrap**: Laravel boots once instead of on every
request. That saving is a fixed amount of work per request, so it looks largest on fast,
CPU-bound routes and represents a smaller share of a request that spends most of its time
waiting on a database or an API.

That is a claim about *proportion*, and it is worth being careful with, because two other
things move at the same time and both get mistaken for it:

**PHP-FPM's pool size caps concurrency.** Under FPM a request occupies a worker for its whole
duration, including time spent waiting. On the simulated-I/O route at 100ms, a pool of 20
workers cannot exceed roughly 200 requests/sec however fast the hardware is. If your
connection count is above `pm.max_children`, you are measuring the pool, not the framework.
BenchKit detects the pool size and flags the run when this happens.

**Neither side is tuned by default.** A stock FPM pool against a stock FrankenPHP is not a
verdict on either. Compare tuned against tuned, and say which tuning you used.

::warning
If you plan to publish a FrankenPHP-vs-FPM comparison, check the pool warning on the load-test
panel first. The most common way to produce a dramatic and wrong result is to hold 50
connections open against a 5-worker pool.
::

::tip
Run the suite on `fpm-nginx` and on `frankenphp` worker mode, open both in **Compare**, then
raise the **Simulated I/O response** and re-run. Watching how the gap changes as I/O grows is
more informative than either number on its own. See
[the web-server load test](/docs/benchmarks/web-server-load-test).
::
