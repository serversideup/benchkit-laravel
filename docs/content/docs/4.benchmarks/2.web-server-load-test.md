The load test drives four routes with [oha](https://github.com/hatoo/oha), each served **without session/CSRF middleware** so it measures the framework request path rather than session bookkeeping:

- **Static** — a plain string. The framework ceiling; no database.
- **JSON API** — a 25-item JSON payload built in PHP.
- **DB read** — 20 rows from a small table (`SELECT … LIMIT 20`).
- **I/O-bound** — sleeps a configurable delay (default **100 ms**) to model a request whose time is dominated by **one outbound dependency call** (a database over a socket, a cache, an HTTP API).

## Why the I/O-bound route exists

Octane/FrankenPHP **worker mode** wins by skipping Laravel's per-request bootstrap. That saving is large on CPU-bound, no-I/O routes (static/JSON) and **shrinks toward nothing once real I/O dominates a request** — because the bootstrap you removed was a small fraction of a request that spends most of its time waiting on the network or database.

The I/O route makes this visible: raise its delay and watch worker mode's lead over PHP-FPM collapse. Compare two runs (`fpm-nginx` vs `frankenphp`) side by side to see it directly.

It is a **simulated** delay, labeled as such everywhere. It models the *latency profile* of an I/O-bound request; it is not a real network call (that would add non-reproducible variance and an external dependency). A blocking sleep also holds a worker for its duration — itself a realistic lesson about worker-pool saturation under I/O concurrency.

## Warmup and duration

Each route is **warmed up** (a short, discarded load pass) before the measured window, so a cold OPcache/JIT, an unprimed route/config cache, and a just-booted worker don't land in the numbers. The default measured window is **30s** (Full preset) or **10s** (Quick preset), overridable per run and always disclosed alongside the result.

::note
Bars in the results scale **within each route** (to its own slowest percentile), so the I/O route's much larger latency doesn't flatten the others into unreadable stubs. The absolute milliseconds sit beside each bar for cross-route comparison.
::
