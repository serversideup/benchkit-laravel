BenchKit is built to give **realistic, comparable** numbers for Laravel on a given machine and image — and to be honest about what it does and doesn't test. This section states the methodology plainly so you can trust the numbers for what they are and not over-read them.

The one rule that matters most:

::warning
**Measure your own real workload before drawing conclusions.** Not the hello-world number in an announcement post, and not a synthetic benchmark — including this one. BenchKit is a comparison and learning tool, not a substitute for profiling your actual application.
::

## What BenchKit measures

| Stage | Tool | What it tells you |
| --- | --- | --- |
| Hardware | [YABS](https://github.com/masonr/yet-another-bench-script) (Geekbench, fio) | Raw CPU and disk throughput of the box |
| Network | [cfspeedtest](https://github.com/code-inflation/cfspeedtest) | Latency/bandwidth from the box to Cloudflare's edge |
| Web server load | [oha](https://github.com/hatoo/oha) | Requests/sec and latency for four representative routes |
| PHP database (CRUD) | [phpbench](https://phpbench.readthedocs.io/) | Per-operation timing of Create/Read/Update/Delete |

## Reproducibility

Every run records the environment that produced it — PHP version and SAPI, serving mode (FPM vs. worker), a curated snapshot of performance-relevant `php.ini` directives (OPcache/JIT, memory, realpath cache…), the FPM pool size when detectable, the database engine, hardware, and the exact load settings. That record lives in the result's **Environment panel** so a number can always be traced back to the configuration behind it.
