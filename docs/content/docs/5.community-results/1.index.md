title: Submitting your results

Finished runs can be added to the [community results gallery](/results): a public dataset of
real BenchKit runs across different hosts, hardware, and PHP configurations.

Submitting is optional. BenchKit never sends anything anywhere on its own, and a run only
leaves your machine when you click the button.

## How to submit

1. Finish a run.
2. Click **Submit result** and fill in where it ran — provider, plan, and what you pay. Your
   specs are detected automatically; the host details are the part only you know.
3. Review the summary of exactly what will be published, then continue.
4. The button opens a pre-filled GitHub issue. Post it.
5. A bot validates the run and opens a pull request. A maintainer merges it, and your run
   appears in the gallery.

The GitHub round trip is deliberate. It means your submission is credited to your GitHub
account without BenchKit needing accounts, logins, or a server of its own, and it means every
result in the gallery arrived through a reviewable pull request.

::note
If validation fails, the bot closes the issue and says why. Nothing is silently dropped.
::

### Why the results block is not readable

The issue shows your run's headline numbers as plain markdown, then folds the submission
itself into a collapsed block of characters beginning `bk1.`. That block is **compressed, not
encrypted** — there is nothing in it that isn't in the table above it, and the bot expands it
into a readable JSON file in a pull request anyone can review before it merges.

It's compressed because it has to fit in a URL. Results used to travel as formatted JSON,
which GitHub truncated part way through — a run would arrive cut off mid-number with nothing
to signal it. Compressed, even the largest run is a fraction of that limit.

The token also ends in a checksum, so the bot can tell a complete, unmodified submission from
one that was cut short or edited on the way. If something is wrong with yours, the bot says
which of those it was.

You can unpack a token yourself at [check a submission](/results/submit) — paste it and the
page shows the full document, runs the same validation the pull request will, and tells you
whether it would be accepted. Nothing is uploaded; it all happens in your browser.

### Can results be faked?

Not usefully by accident, and not casually on purpose.

Once a run is accepted, its measurements are sealed with a SHA-256 digest stored alongside
them. Every pull request and every site build recomputes that digest, so changing any
number — in review, or in a commit to `main` months later — fails CI from then on. Your host,
plan, and cost sit outside the seal, because a maintainer correcting a misspelled provider
name shouldn't break anything.

What that can't do is prove a number was honestly measured. BenchKit is open source and runs
on hardware you control, so someone determined enough could produce whatever they wanted —
that's true of any self-hosted benchmark, and no checksum changes it. What the seal removes
is the easy stuff: truncation, a mangled paste, a value nudged in the issue body, a quiet
edit after merge.

So the gallery is built around unverified data rather than pretending otherwise — see
[how to read the gallery](#how-to-read-the-gallery) below.

## What gets published

The app sends an **allow-list**. A field is published because someone chose to publish it,
not because nobody thought to remove it.

**Published**, because it explains the numbers:

- CPU model and core count, RAM, OS
- PHP and Laravel versions, image variation, SAPI, whether Octane is running
- Performance-relevant `php.ini` values: OPcache sizing, JIT, realpath cache
- FPM pool size, when there is one to detect
- The database engine
- Which stages ran, the load applied, and the results
- The host, plan, and cost you typed in

**Never published:**

| Withheld | Why |
| --- | --- |
| Console logs | They contain your public IP |
| `APP_URL` and internal hostnames | Identifies your network |
| Raw YABS output | Carries an `ip_info` block with IP, ISP, and city |
| Network ASN and Cloudflare colo | On home hardware these are your ISP and nearest city |
| `opcache.preload` path | A filesystem path often carrying a project or company name |
| Non-tag `build_version` | A self-built image tagged `ghcr.io/your-company/...` would leak the company name |

Whether preloading is enabled is published as `opcache.preload_enabled`. Where the file lives
is not.

A second, independent check backs this up. The `validate-run-submission` action scans every
string in the document for IP addresses, filesystem paths, email addresses, private hostnames,
and links to anywhere other than Geekbench, and fails the pull request if it finds one. That
guard covers fields nobody has thought about yet, so adding data later cannot quietly start
publishing something it shouldn't.

If you spot something in the gallery that shouldn't be public, please
[open an issue](https://github.com/serversideup/benchkit-laravel/issues).

## How to read the gallery

These numbers are **community-submitted and unverified**. BenchKit runs on hardware the
submitter controls, so no single run can be independently proven. The gallery is built around
that rather than pretending otherwise:

- It shows a distribution, not a leaderboard. A ranking across different hardware, settings,
  and image variations would be meaningless.
- Filter to one image variation and one provider before comparing anything.
- Runs added by the BenchKit team are marked **Maintainer**. That badge is not self-serve.
- Costs are stored in the currency the submitter is billed in and are never converted. Any
  exchange rate we shipped would be wrong by an unknown amount and get worse over time, so
  the gallery ranks value within one currency at a time instead.

Please don't submit fabricated or manipulated results. The gallery is only worth having if the
numbers in it are real.

## Where the data lives

Every submitted run is a JSON file in
[`docs/data/runs`](https://github.com/serversideup/benchkit-laravel/tree/main/docs/data/runs),
published as a static API:

| Endpoint | Contains |
| --- | --- |
| `/api/results/index.json` | Every run, summary fields only |
| `/api/results/<run id>.json` | One run, in full, including its integrity digest |

It's a stable public dataset. If you'd rather plot it yourself than use the gallery, fetch it
directly.
