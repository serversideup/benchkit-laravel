## How does BenchKit work?

BenchKit is a standalone Laravel application built "container first" so you can easily benchmark your VPS or hosting provider. It uses [YABS](https://github.com/masonr/yet-another-bench-script) to test hardware, [cfspeedtest](https://github.com/code-inflation/cfspeedtest) for the network, [oha](https://github.com/hatoo/oha) to load-test the web server (including a simulated-I/O route), and [phpbench](https://phpbench.readthedocs.io/) for PHP CRUD. See [Methodology](/docs/benchmarks) for exactly what each test measures.

## Do I install this as a Laravel package?

No. BenchKit is a **standalone application** you run and then destroy once you're done — not a package you add to your app.

## Can I run it without Docker?

Yes. You can clone the repo and run it on a PaaS (Laravel Cloud, DigitalOcean App Platform, etc.), though you'll need the benchmark tools available on the host. See [Deployment options](/docs/getting-started/deployment-options).

## How do I benchmark Laravel Octane / FrankenPHP?

Use the [`frankenphp`](/docs/image-variations/frankenphp) image — the same image runs classic and worker mode, so results are directly comparable. Run once on `fpm-nginx` and once on FrankenPHP worker mode, then open both in **Compare**.

## Can I benchmark against MySQL or Postgres?

Yes — it's standard Laravel config with the `DB_*` environment variables, and BenchKit creates its tables on demand (no migration step). See [Adding a real database](/docs/configuration/adding-databases).

## How accurate are these numbers?

BenchKit aims for realistic, comparable numbers and is upfront about its limits — a co-resident load generator, SQLite by default, a single concurrency point, and coordinated-omission-affected tail latency. Read [Methodology](/docs/benchmarks) and [Known limitations](/docs/benchmarks/limitations) before drawing conclusions. The short version: **measure your own real workload.**

## Does my run history survive rebuilding the container?

Only if you mount a volume at `storage/app/runs` (the `-v benchkit-runs:/var/www/html/storage/app/runs` flag). Without it, history lasts only as long as the container. See [Deployment options](/docs/getting-started/deployment-options).

## How can I share results with the community?

When you finish a run, you can share it to X with the **#BenchKit** hashtag. Browse the [live #BenchKit feed](https://x.com/search?q=%23BenchKit&f=live) to see what others are running.
